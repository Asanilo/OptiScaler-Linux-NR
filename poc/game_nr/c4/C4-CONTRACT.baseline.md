## First implementation scope

New C4 native/client and Helper files and artifacts. Keep C3's 1920x1080 HDR Run, DLAA 1:1, actual current/previous jitter zero, full valid rect, same-texel real depth and MV, WorkingScale1, one pass, manual WhitePoint1 and explicitly unknown game exposure. Same production encode/Evaluate/resolve algorithms and pinned runtime dependencies. One resident PID/device/feature/resource set, one in-flight frame. No lower resolution, frame skipping, stale-frame display, external semaphore repair, FG or global configuration changes.

CLI `resident|skipEvaluate RUN_DIR_WINDOWS SESSION`. Config has `protocol_version:4`, `execution_mode:"hot"|"diagnostic"`, matching mode, `frame_count`=`max_frames` integer 4,120,1800 or18000. Diagnostic and skipEvaluate initially allow only4. `diagnostic_case` is smoke,static,motion,sustained or skipEvaluate. All config choices must be validated before allocation; C3-only peers cannot accept C4. Setup metadata and every control envelope carry protocol_version4 and execution_mode; reject mismatches rather than inferring from missing fields. C3 resource descriptors, filenames, strict JSON wire-value comparisons, setup/baseline/imported/raw-FD-consume/fd-retired handshake are otherwise reused.

Every frame retains session/generation/frame/resource_set, source_game_frame/prev_source_game_frame, history_version1, params_version1, actual SR reset/jitter/history/profile/validrect/exposure fields, dynamically derived nr_reset/reset_reason. Same first/SR-reset/source-gap/continuous rules as C3. Modes and profile versions must be echoed exactly. First generation is0; first iteration does not implement resize or parameter mutation. Terminal frame is frame_count, source is last processed source. No unbounded file queue or more than one active slot.

## Hot versus diagnostic

Hot is the default. Both ends omit full-image validators, source/output signatures, CPU full pixel readbacks/scans/FNV/dumps and their dedicated buffers/pipelines. Keep production keep/proxy/raw/resolve resources and required input/output conversions; do not remove algorithmic work. Preserve raw NaN/output -1234 GPU clears initially. Each resident frame actually calls Evaluate once/result1 and resolve once, with cumulative counters. API return, real GPU fence completion and strict active tuple form hot model acceptance; this does not claim numerical, alpha, poison-coverage, transport-signature or visual-quality validation.

Hot envelopes explicitly use `validation_profile:"c4_hot_path"`, `audit_kind:"off"`, `numerical_validation:"NOT_CHECKED"`, `pixel_validation:"NOT_RUN"`, `signature:"NOT_RUN"`, `dump_count:0`. Do not include C3 finite/written/alpha/signature/FNV counters filled with constants. Helper pixel readback bytes0; native guard bytes4 is explicit. Query-result bytes are telemetry, counted separately. Output-valid/model-valid booleans refer to actual API/GPU/identity checks only; logs and reports must state that scope.

Diagnostic4 uses the same C4 production model/resource/conversion path with the C3 full per-frame validator/readbacks/signatures/dumps, labelled `validation_profile:"c4_diagnostic"`, `audit_kind:"full"`. It is a separate run, excluded from the hot performance window. Preserve exact C3 numerical checks and negative skipEvaluate checks. It provides correctness evidence for the new artifact, not proof of every uninspected hot pixel. Diagnostic native may acquire Color+Output as C3 requires; hot return acquires Output only. Never read Color while its ownership remains EXTERNAL.

skipEvaluate retains encode/poison, API result/calls/resolve0, INVALID/output_valid=false/model_valid=false; the same normal predicate rejects it. Diagnostic proves poison and SR fallback. No invalid return is merged.

## Required native conversion guard

In the existing output conversion dispatch, after loading RGBA32F and before storing RGBA16F, test every component for NaN, infinity or abs(value)>65504. Any failure atomically ORs a persistent4-byte SSBO flag and skips that texel store. Do not clamp or silently alter the source. Normal pixels need no atomic. A nonzero flag rejects the entire return, keeps immutable original SR, and enters the existing abort/quarantine path; partially written return is never selected.

Clear flag every frame via vkCmdFillBuffer0. Barrier TRANSFER_WRITE to COMPUTE SHADER_READ|SHADER_WRITE before conversion. After conversion, HOST_READ visibility covers both TRANSFER|COMPUTE stages and TRANSFER_WRITE|SHADER_WRITE access, including normal zero where no shader write occurs. Read/invalidate only after actual bounded output submission completion. Persistent allocation remains alive until final GPU use. Report actual `guard_flag`, `guard_readback_bytes:4`, `guard_profile:"finite_abs_le65504"`. This conservative guard is not C3 actual-half/alpha/count/signature validation. Diagnostic still checks actual half values independently. Any fault test for the guard uses separately pinned test-only input injection, never changes the production model to produce a passing result.

## Scheduling, failure and presentation

Retain actual current input Flush+bounded completion before INPUT_READY, EXTERNAL/GENERAL ownership, Helper actual fence before completion, native output Flush+fence before flag/consumed, and actual prior merge GPU-last-use before next slot overwrite. Reacquire command buffers after Flush. Return image ShaderRead visibility for merge remains mandatory. Original SR image stays unmodified. Every selected output has exact same-source merge/next-VideoOut binding and unique non-reused Present ledger; source+1/draw-tick guard and pending-ledger backpressure remain. Bypass and failures are explicitly counted, never counted as NR frames.

Initial finite bounds remain cold120s/control60s/GPU10s/frame30s for this measured prototype; these are failure upper bounds, not acceptable interactive latency. Report stalls including failure waits. C4 is not declared playable solely because those bounds are finite. Measure and reduce interactive wait policy after evidence; no silently shortened timeouts or relaxed acceptance. A result first observed past deadline is permanently invalid, no sample/merge/reuse. Peer exit and abort must wake bounded waits. Release only after own GPU completion and peer drain or verified private process exit. Abnormal cleanup never claims normal FD reclamation.

Normal final lifecycle retains native-released/retired/audited, model/core/module shutdown and actual wait/reap0, full FD inventories and all owned DMA-BUF payload identity retirement. Global game FD churn and unreadable sampling slots must be reported separately, not mislabelled leaks or exact equality.

## Measurement and acceptance

Helper uses a persistent timestamp pool; per-frame reset and markers bracket acquire/poison, encode, Evaluate-recorded commands, resolve and release. Read64-bit results plus availability only after the existing fence; no additional WAIT_BIT. Record timestampValidBits, period, wrap handling, availability, timing scope and query readback bytes. Unavailable values are null/NOT_AVAILABLE, never zero-time PASS. Evaluate interval includes recorded dependencies/scheduling and is not a pure model benchmark. Also record actual CPU Evaluate call, fence wait, control read/publish and frame wall time.

Native records prior-merge wait, input Flush/wait, peer completion wait, output Flush/wait, conversion GPU intervals and guard overhead where measurable, plus merge/Present evidence. GPU timing values from separate queues/devices are durations only, not comparable absolute clocks. Use actual monotonic CPU phase timestamps to correlate source-to-selection/presentation; do not call that input-to-photon latency.

Root runs serially: diagnostic4 normal+skip; hot4 correctness/visible output; hot120; matched SR-only versus NR static/motion performance windows; then sustained active play, load/exit/recovery. Root can request a few presentation captures outside the scored hot window. Every benchmark names warmup/window, source IDs, actual Evaluate/accepted NR counts, SR fallback counts, dimensions/WorkingScale, game cap and effective settings. Both matched profiles use BB_FPS=uncap plus BB_FPS_LIMIT=90. Count all stalls; report observed FPS and p50/p95/p99 frame time, NR GPU/CPU/control waits and extra CPU-observed latency separately. Record global device memory once and process allocation counts separately, never double-count shared allocation as two physical copies.

Target is near60FPS with limited loss from the user's90+ SR baseline, subject to actual RTX4060 Laptop8GB measurements. A lower result is reported directly. Removing diagnostics is a hot-path improvement, not a faster NR model. No skipped Evaluate or lower resolution can be credited as equivalent full-resolution NR improvement.

At least one actual sustained-play run must state duration and observed load/exit/recovery behavior before C4 playable acceptance. The first bounded hot benchmark is an intermediate gate, not whole-C4 completion. If serial scheduling remains too slow, identify measured costs before proposing ring/pipeline work. Parameter UI and safe model rebuilds follow under C5; unsupported controls stay disabled. No new broad framework or guessed SDK parameter semantics in this first C4 change.
